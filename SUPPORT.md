# Support

## Getting help

Before asking for help:

1. Review the [README](README.md), [architecture documentation](docs/ARCHITECTURE.md), and [implementation plan](docs/implementation-plan.md).
2. Search [existing issues](https://github.com/QuinntyneBrown/word-up/issues) for the same problem.
3. Confirm the problem still occurs on the latest `main` branch with supported .NET and Node.js versions.
4. For backend integration-test failures, record the SQL Server target and whether `WORDUP_TEST_SQLSERVER` or `WORDUP_TEST_SQLAUTH` is set.

For reproducible defects or scoped improvements, open a [GitHub issue](https://github.com/QuinntyneBrown/word-up/issues/new).

Include expected and actual behaviour, reproduction steps, relevant environment details, linked L2 requirement IDs when applicable, and sanitized logs or screenshots. Never post credentials, signing keys, connection strings, participant data, consent records, invitation or reset tokens, or security vulnerabilities.

## Security and conduct

- Report vulnerabilities privately according to [SECURITY.md](SECURITY.md).
- Report conduct concerns through the private channel described in [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

Support is provided by project maintainers and contributors on a best-effort basis. This repository does not include a service-level agreement, production operational support, or participant support services.
