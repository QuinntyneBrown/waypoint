# L2 — Application Intake (INTAKE)

Each L2 traces to an L1 in `application-intake/L1.md`.

## L2-INTAKE-001: Application/referral form captures applicant, guardian, and consent data
**Traces to:** L1-INTAKE-001

The application form must capture who is filling it out (self / guardian / referrer), youth details, guardian contact, neighbourhood, cohort of interest, track interest, motivation, and consent/privacy acknowledgements, and must enforce eligibility and under-18 guardian rules.

**Acceptance Criteria:**
1. Given the application form, when submitted, then first name, last name, age, neighbourhood, "why interested", the participation-consent checkbox, and the privacy-policy checkbox are required; missing/invalid values block submission with field-level errors.
2. Given an applicant age indicates a minor (under 18), when submitting, then guardian name, guardian email, and guardian phone are required.
3. Given an applicant's age, when submitting, then only ages 12–18 inclusive (confirm with product owner) are accepted; an application with an age outside 12–18 is rejected with a message stating the eligible ages (12–18 inclusive), and this range is enforced consistently in validation.
4. Given a valid submission, when it succeeds, then the application is recorded with status "New", the applicant sees the confirmation/next-steps page, and no account is created yet.
5. Given input fields, when submitted, then all free-text is validated and sanitized server-side (see L2-NFR-001).

## L2-INTAKE-002: Applications flow through an admin review pipeline to enrollment
**Traces to:** L1-INTAKE-002

Each application must move through review states and, on approval, be placed into a cohort with an assigned mentor, creating the youth account/enrollment; declines are soft with an optional note.

**Acceptance Criteria:**
1. Given a submitted application, when an admin reviews it, then they can set track interest, assign a cohort (required to approve), assign a mentor (required to approve), and add a decision note.
2. Given an application for a minor without recorded guardian consent, when viewed, then its status is "Needs consent" and it cannot be fully approved into active participation until consent is satisfied (see L2-CONSENT-002).
3. Given an admin approves an application, when confirmed, then a Youth account and youth profile are created (or linked), enrolled in the chosen cohort under the chosen mentor, and the applicant is notified per configured channels.
4. Given an admin declines an application, when confirmed, then its status becomes "Declined", the optional note is stored on the record, and no account is created.
5. Given approve/decline actions, when performed, then only Program Administrators may perform them (see L2-AUTH-009) and each action writes an audit entry (see L2-CONSENT-003).
