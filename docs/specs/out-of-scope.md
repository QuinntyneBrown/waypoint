# Waypoint — Out of Scope / Deferred (v1)

Features below were present in the specification but are **not authorized by the PRD** (`docs/PRD.md`), the single source of truth. They have been removed from the L1/L2 requirements and recorded here with rationale so nothing is lost. Retired requirement IDs are **not reused**. Revisit each only if the PRD is expanded and the product owner prioritizes it.

| # | Feature | Why out of scope (vs PRD) | Removed from | Revisit when |
|---|---|---|---|---|
| 1 | **PIN sign-in for shared devices** — short numeric PIN bound to a youth account as a fast alternative to email/password | PRD specifies only email/password, invite-based authentication and "secure data handling"; a device-bound PIN path is added scope | `L1-AUTH-002`, `L2-AUTH-002` (removed) | Fast youth sign-in on shared/kiosk devices is prioritized and its security tradeoffs approved |
| 2 | **Switch-user / recent-accounts picker** — multi-account switcher listing remembered accounts on a shared device | PRD requires secure data handling (kept as secure sign-out + idle-timeout expiry) but not a multi-account switcher | `L1-AUTH-006`, `L2-AUTH-007` (descoped; secure sign-out + idle expiry retained) | Multi-user shared-device workflows are prioritized |
| 3 | **Offline beyond attendance** — offline lesson reading, offline reflection/quiz drafting, and offline submissions with local queue + sync | PRD authorizes only "offline attendance" | `L1-NFR-003`, `L2-NFR-004` (narrowed to attendance); `L2-LEARN-002/004/006`, `L2-PLATFORM-012` (offline clauses removed) | A PRD revision authorizes broader offline learning |
| 4 | **Real-time domain event bus** — live fan-out of nine domain events (progress, quiz graded, submission reviewed, badge awarded, attendance saved, announcement posted, youth flagged, …) | PRD names only "notifications"; scope kept to near-real-time notification & message delivery | `L1-NFR-004`, `L2-NFR-005` (narrowed to notifications/messages) | A PRD requires live, non-notification domain updates |
| 5 | **Internationalization / localization** — user-selectable display language (English/French/Spanish/Portuguese) and locale-sensitive formatting | PRD contains no i18n/multi-language requirement | `L1-NFR-010`, `L2-NFR-012` (removed); `L2-PLATFORM-004` (language selection removed) | The program expands to non-English cohorts or the PRD adds a language requirement |
| 6 | **Coding cohort gallery** — publishing approved youth coding projects to a consent-gated cohort showcase | PRD covers coding lessons/projects and mentor review, not a shared showcase; raises unaddressed safeguarding surface | `L1-LEARN-003` (gallery clause), `L2-LEARN-008` (gallery ACs) — coding lessons + reviewable projects retained | A safeguarded showcase with an explicit consent model is introduced |
| 7 | **Google Workspace / Drive integration** — org-level connect/disconnect with server-side credentials | PRD's admin capabilities do not include any third-party file/identity integration | `L1-ADMIN-004`, `L2-ADMIN-006 AC5` (removed) | A document-storage or SSO integration is added to the PRD |
| 8 | **Live Google Sheets export/sync** — two-way report/progress-board sync to a connected Google workbook | PRD scopes export to CSV/PDF and imports to CSV roster migration only | `L1-REPORT-003`, `L2-REPORT-003 AC2/AC4` (Google Sheets removed; CSV/PDF export + CSV import retained) | An org requests outbound spreadsheet integration (evaluate credential/safeguarding constraints) |
| 9 | **Custom report builder + saved presets** — ad-hoc report configuration (data set, filters, columns, format) with reusable presets | PRD calls for reporting via fixed standard reports, not self-service report building | `L1-REPORT-002`, `L2-REPORT-002` (removed) | Staff need self-service configuration beyond the standard reports |
| 10 | **Global search** — cross-entity search across people, lessons, and cohorts | No PRD basis for a cross-entity search capability | `L1-PLATFORM-001`, `L2-PLATFORM-001` (removed) | A PRD revision adds cross-entity discovery needs |
| 11 | **Web push channel + quiet hours** — browser push delivery and do-not-disturb scheduling for notifications | PRD "notifications" is satisfied by in-app (with optional email); push infra and quiet-hours scheduling are added scope | `L2-PLATFORM-003` (push + quiet hours removed; in-app + optional email retained) | A mobile/push delivery or do-not-disturb requirement is added |
| 12 | **RSVP capacity limits & waitlisting** — enforced event capacity with waitlists (e.g. retreats) | PRD RSVP is a simple going/maybe/can't-attend response | `L2-ENGAGE-005 AC4` (removed) | Event/retreat capacity management is prioritized |
| 13 | **Auto-logged volunteer hours** — hours derived from attendance and totalled per term | PRD limits volunteers to assigned-session, schedule, and attendance access only | `L1-VOLUNTEER-001` (wording), `L2-VOLUNTEER-002 AC2` (removed) | Volunteer time/hours reporting is added to the PRD |

### Also noted
- **Federated (Google) sign-in** — not specified as a requirement; v1 uses email/password invite-based auth. (Appendix A-8.)
- **Light/dark theme toggle** — not in v1; display preferences cover text size, contrast, motion, and reading font. (Appendix A-10.)
- **Operational admin CLI** (`L1-NFR-008` / `L2-NFR-011`) is retained but labelled **operational tooling (out-of-band)**, not product scope — it is an ops interface, not a user-facing capability.
