# L1 — Authentication & Access (AUTH)

High-level requirements for authentication, account provisioning, sessions, authorization, and onboarding.

## L1-AUTH-001: Credential authentication
The system must authenticate users by email and password, issue a session on success, distinguish unrecognized email from incorrect password without disclosing which, and support an optional "remember me" that is discouraged on shared devices.

## L1-AUTH-003: Invitation-based account provisioning
The system must be invite-only: staff create role-scoped invitations (Youth, Mentor, Guardian, Volunteer) delivered by email; an invitee accepts by setting a display name and password; invitations expire and can be resent or revoked.

## L1-AUTH-004: Password reset
The system must let a user request a password-reset link by email, follow the emailed link to set a new password under a defined policy, and confirm success, without disclosing whether an email exists.

## L1-AUTH-005: Account lockout & brute-force protection
The system must temporarily lock an account after too many failed sign-in attempts, communicate the lock and its duration, and offer recovery paths (password reset, contact mentor) during the lock.

## L1-AUTH-006: Shared-device session management
The system must fully close a user's session on sign-out from a shared device and automatically expire sessions after inactivity while preserving unsaved drafts.

## L1-AUTH-007: Role-based access control & authorization
The system must enforce role-based authorization so each persona sees and does only what its role permits, including resource-scoped rules (a mentor accesses only their assigned youth/cohorts; a youth only their own data; a guardian only their child's shared data; a volunteer only session/attendance operations).

## L1-AUTH-008: First-run onboarding
The system must guide a newly provisioned youth through onboarding (display name, pronouns, optional photo, cohort confirmation, default notification preferences) with the ability to skip.

## L1-AUTH-009: Credential & token security
The system must protect authentication secrets: enforce a defined password policy, store passwords using strong adaptive hashing, and issue short-lived access tokens with rotating, reuse-detected, hashed-at-rest refresh tokens.
