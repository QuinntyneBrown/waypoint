# L1 — Non-Functional & Quality (NFR)

Cross-cutting quality attributes that apply across all functional subsystems.

## L1-NFR-001: Security
The system must be secure by design against the OWASP Top 10 — enforcing authentication and authorization on every request, validating and sanitizing all input, protecting against injection/XSS/CSRF, applying security headers and HTTPS, and rate-limiting sensitive endpoints. (Credential/token specifics live in AUTH — see L1-AUTH-009.)

## L1-NFR-002: Data privacy & PII protection
The system must protect personal data — especially minors' — by collecting only what is needed, restricting access to staff and assigned mentors, honouring consent (including withdrawal), supporting data-subject requests (access, correction, removal), and retaining data only as long as needed.

## L1-NFR-003: Offline attendance capture & synchronization
The system must let volunteers and mentors capture attendance offline, queuing those writes locally and syncing them automatically and safely (without loss or duplication) on reconnect.

## L1-NFR-004: Near-real-time notification and message delivery
The system must deliver notifications and messages to relevant clients in near-real-time, scoped to authorized recipients, with graceful reconnection.

## L1-NFR-005: Performance & scalability
The system must meet defined performance targets for response time, throughput, and resource use under expected load, and remain responsive on low-powered shared Chromebooks.

## L1-NFR-006: Responsive design
The system must render correctly and usably across all viewport sizes — extra-small (<576px), small (≥576px), medium (≥768px), large (≥992px), and extra-large (≥1200px) — with mobile-first layouts for youth/guardian/volunteer and adaptive layouts (including horizontally scrollable data tables/matrices) for staff.

## L1-NFR-007: Accessibility
The system must meet WCAG 2.2 AA — 44px+ tap targets, real form labels, sufficient contrast, status never conveyed by colour alone, keyboard operability, focus management for dialogs, and screen-reader-appropriate semantics — and honour user accessibility preferences.

## L1-NFR-008: Observability & operations
The system must expose health/readiness checks, emit structured logs with secrets redacted, record request logging, and provide the operational surface needed to run, seed, migrate, and support the platform — including an admin CLI that is operational tooling (an out-of-band ops interface), not product scope.

## L1-NFR-009: Reliability & data integrity
The system must protect data integrity under concurrency (optimistic concurrency on mutable records such as attendance and submissions), warn on unsaved changes before navigation, make sync/submit operations idempotent, and keep progress/records safe across failures.
