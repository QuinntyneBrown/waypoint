# L2 — Learning Experience (LEARN)

Each L2 traces to an L1 in `learning-experience/L1.md`.

## L2-LEARN-001: Curriculum browsing and progression gating
**Traces to:** L1-LEARN-001

Youth must browse their track's modules/lessons with correct gating and unlock rules.

**Acceptance Criteria:**
1. Given a youth's enrolled track, when they open curriculum, then only published modules are listed with per-module status (done / in progress / locked) and completion %.
2. Given a locked module, when a youth attempts to open it, then access is denied until its prerequisite module is complete, and the unlock condition is shown.
3. Given a module, when opened, then lessons and the module quiz are ordered, with later lessons/quiz locked until earlier items complete; server-side checks enforce this (a locked lesson cannot be completed by direct request — see L2-AUTH-009).
4. Given a youth enrolled in multiple tracks, when they switch track, then the displayed curriculum reflects the selected track.
5. Given no modules are published for a track, when opened, then an empty "not set up yet" state is shown.

## L2-LEARN-002: Lesson delivery and completion
**Traces to:** L1-LEARN-002

Youth must experience a lesson (scripture, teaching, optional media, reflection prompt) and mark it complete, which routes them to the reflection.

**Acceptance Criteria:**
1. Given a lesson, when opened, then it shows scripture block(s), teaching content, step progress, an adjustable reading text size, and optional media; leader-guide notes are never shown.
2. Given a youth reads a lesson, when they bookmark or adjust text size, then the preference/position persists for resuming.
3. Given a youth chooses "mark complete", when confirmed, then the lesson is marked complete for the youth with a timestamp, gating for subsequent items updates, and the youth is routed to the reflection (see L2-LEARN-003 reflection).
4. Given optional lesson media fails to load, when accessed, then the lesson's scripture and teaching text stay fully readable and a retry control is offered for the failed media.

---

## L2-LEARN-003: Reflections with privacy control
**Traces to:** L1-LEARN-006

Youth must write reflections with a mood check-in and per-reflection sharing choice, with draft support.

**Acceptance Criteria:**
1. Given a reflection, when submitted, then the primary reflection text is required; the mood/engagement selection is captured; optional secondary prompts are saved.
2. Given the sharing toggle, when left off (default), then the reflection is private to the youth; when on, then the assigned mentor may read and reply in check-ins.
3. Given unsaved reflection content, when the youth navigates away, then they are warned and can save a draft (see L2-NFR-007).
4. Given a saved draft, when the youth returns, then the draft content is restored.

---

## L2-LEARN-004: Quiz taking, autosave, and immutability
**Traces to:** L1-LEARN-004

Youth must take quizzes one question at a time with autosave and immutable-on-submit behavior within attempt limits.

**Acceptance Criteria:**
1. Given a quiz intro, when shown, then it states the number of questions, estimated time, attempts allowed, pass mark, and any badge reward, and the current attempt number.
2. Given a quiz in progress, when a youth answers and navigates, then answers autosave and the quiz is resumable at the same position after an interruption while online.
3. Given the final question, when the youth submits, then a confirmation warns answers cannot be changed for that attempt; on confirm, the attempt is scored server-side against the pass mark.
4. Given attempts are exhausted, when the youth tries again, then further attempts are refused; the number of attempts allowed is the quiz's configured attempt limit, and the recorded score is the best passing attempt within that limit (confirm with product owner).
5. Given a submitted attempt, when scored, then answers for that attempt are immutable.

---

## L2-LEARN-005: Quiz result and review
**Traces to:** L1-LEARN-004

Youth must see their score, pass/fail, per-question review, and any earned badge, subject to the quiz's feedback mode.

**Acceptance Criteria:**
1. Given a scored attempt, when the result loads, then it shows the score, pass/fail against the pass mark, and (per feedback mode) a per-question review marking correct answers and the youth's wrong selections.
2. Given a passing attempt that triggers a badge rule, when finalized, then the badge is awarded and shown, once.
3. Given a quiz requires mentor approval before it counts, when the youth views the result, then the score shown is the approved score once approved; the youth never sees an unapproved/override-hidden score (see L2-MENTOR-004).
4. Given retake is allowed and attempts remain, when the youth chooses retake, then a new attempt begins.

## L2-LEARN-006: Assignment brief and submission
**Traces to:** L1-LEARN-005

Youth must view an assignment brief (rubric, due date) and submit work of the allowed types with an attestation.

**Acceptance Criteria:**
1. Given an assignment, when opened, then it shows the task, due date/time, allowed submission types, and a rubric preview with points.
2. Given the submission form, when submitted, then required fields for the allowed types are enforced (e.g., photo required when photo is the required type; reflection text required), plus the truthfulness attestation.
3. Given a photo upload, when selected, then file type (JPG/PNG) and size (≤ configured max, e.g. 10 MB) are validated and the file is stored/served safely (see L2-NFR-001).
4. Given a submission is confirmed, when sent, then the youth's submission is recorded with status "Submitted", it becomes read-only to the youth (no edits after submit), and the youth is routed to submission status.

---

## L2-LEARN-007: Submission status lifecycle (youth view)
**Traces to:** L1-LEARN-005

Youth must track a submission through Under review → Approved or Needs revision, see mentor feedback, and resubmit on revision.

**Acceptance Criteria:**
1. Given a submitted assignment, when under review, then the youth sees a timeline (Submitted → Under review → outcome pending) and a copy of what they submitted.
2. Given a mentor approves, when the youth views status, then it shows Approved, the rubric points awarded, any badge unlocked, and the mentor's comment (see L2-MENTOR-003).
3. Given a mentor requests revision, when the youth views status, then it shows Needs revision with the mentor's note and a path back to resubmit; resubmission returns to Under review.
4. Given a status change, when it occurs, then the youth receives a notification and (if connected) a real-time update (see L2-NFR-005).

---

## L2-LEARN-008: Coding lesson and project delivery
**Traces to:** L1-LEARN-003

Youth must complete interactive coding lessons and submit coding projects for mentor review.

**Acceptance Criteria:**
1. Given a coding lesson, when delivered, then it shows stepwise content, code samples, an in-lesson editor/preview, and a completion checklist; marking complete records progress toward the relevant badge.
2. Given a coding project, when submitted with an optional note to the mentor, then it enters the same review lifecycle as assignments (see L2-LEARN-007).

---

## L2-LEARN-009: Learner journey and badges view
**Traces to:** L1-LEARN-007

Youth must see their journey roadmap and badge collection with unlock criteria and progress.

**Acceptance Criteria:**
1. Given the journey view, when loaded, then modules are shown as done/in-progress/locked with completion counts and the current module highlighted.
2. Given the badges view, when loaded, then earned badges (with earn dates) and locked badges (with criteria and counted progress, e.g. "1 of 3") are shown, plus a milestone timeline.
3. Given badge/journey counts, when derived, then they are computed from a single source of truth so counts are consistent across home, journey, badges, and profile.

---

## L2-LEARN-010: Learner progress self-view
**Traces to:** L1-LEARN-008

Youth must see personal analytics across overview, quizzes, and attendance.

**Acceptance Criteria:**
1. Given the progress view, when loaded, then it shows overall progress, quiz average, lessons completed, and attendance rate.
2. Given the quizzes tab, when loaded, then a quiz history with per-quiz score and pass state is shown.
3. Given the attendance tab, when loaded, then per-session attendance status is shown.
4. Given leadership competencies, when shown, then each competency's current level/percent is displayed, sourced from mentor assessments (see L2-MENTOR-005).
