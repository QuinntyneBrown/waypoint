# L2 — Guardian Portal (GUARDIAN)

Each L2 traces to an L1 in `guardian-portal/L1.md`.

## L2-GUARDIAN-001: Guardian child-progress (read-only)
**Traces to:** L1-GUARDIAN-001

Guardians must see only their child's aggregate progress, attendance, badges, and schedule — never restricted content.

**Acceptance Criteria:**
1. Given a guardian, when the child-progress view loads, then it shows overall progress, per-module completion, attendance history (present/late/excused/absent), earned/locked badges, and upcoming schedule.
2. Given the guardian portal, when rendered, then it exposes no edit controls over child data, no lesson content, no quiz answers, no private reflections, and no mentor private notes.
3. Given a guardian requests any endpoint, when served, then it returns data only for their own linked child and denies others (see L2-AUTH-010).
4. Given check-in items shared with the guardian, when shown, then only explicitly shared content is visible (prayer requests remain private unless shared — see L2-MENTOR-006).

## L2-GUARDIAN-002: Guardian announcements
**Traces to:** L1-GUARDIAN-001

Guardians must read announcements targeted to guardians/their child's cohort.

**Acceptance Criteria:**
1. Given a guardian, when announcements load, then only org/cohort/consent announcements targeted to guardians are shown with unread indicators.
2. Given "mark all read", when used, then unread state clears for that guardian.
3. Given loading/empty conditions, when they occur, then appropriate loading/empty states are shown.

---

## L2-GUARDIAN-003: Guardian consent and contact management
**Traces to:** L1-GUARDIAN-001

Guardians must manage their own contact info and media/participation consent and view the e-sign record.

**Acceptance Criteria:**
1. Given the consent page, when a guardian updates media consent (and granular sub-options), then it persists and the media-consent status updates; participation consent already given is shown read-only with its signer/date/validity (see L2-CONSENT-001).
2. Given contact info, when a guardian edits their name, relationship, email, phone, and emergency contact, then it persists.
3. Given "view e-sign record", when opened, then the signer, date/time, method (typed e-signature), and reference id are shown and a copy can be emailed.
4. Given a guardian may only manage their own record, when they attempt another guardian's/child's data, then it is denied (see L2-AUTH-010).
