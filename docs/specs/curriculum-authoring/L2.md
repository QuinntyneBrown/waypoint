# L2 — Curriculum Authoring (CURRIC)

Each L2 traces to an L1 in `curriculum-authoring/L1.md`.

## L2-CURRIC-001: Tracks and modules authoring
**Traces to:** L1-CURRIC-001

Staff must author tracks and modules with ordering, prerequisites, and publish lifecycle.

**Acceptance Criteria:**
1. Given a new track is created, then an author-defined track name and unique track key are captured (tracks are data-driven, not limited to a fixed set), so that Bible, leadership, and coding tracks are all representable; description is captured and publish state is set.
2. Given a track, when a module is added, then name, description, prerequisites (prior module), and scripture anchor are captured, and the module enters Draft.
3. Given modules/lessons in a track, when reordered, then the new order persists and determines youth-facing sequence.
4. Given a module, when its publish state changes (Draft → In review → Published), then a confirmation names the assigned cohorts and, once Published, the module becomes visible to those cohorts' youth.
5. Given only authorized roles (Program Administrator/Mentor per matrix) may edit curriculum, when an unauthorized user attempts an edit, then it is denied (see L2-AUTH-009).

## L2-CURRIC-002: Lessons authoring
**Traces to:** L1-CURRIC-001

Staff must author lesson content including teaching text, media, reflection prompts, and leader guides.

**Acceptance Criteria:**
1. Given a lesson is saved, then lesson title, scripture reference, estimated time, learning objectives, teaching body, reflection prompts, and leader-guide notes are persisted.
2. Given media attachments, when added, then supported types (video/document) are listed and can be removed; uploads are validated for type and size and served safely (see L2-NFR-001).
3. Given the leader-guide notes, when a lesson is delivered to youth, then those notes are never shown to youth (mentor-only).
4. Given a lesson, when published, then it becomes live for youth in assigned cohorts; when set to draft, then youth no longer see it.
5. Given a lesson is deleted, when confirmed, then youth progress for it is archived (not hard-deleted) and any linked quiz remains intact.

## L2-CURRIC-003: Quiz authoring
**Traces to:** L1-CURRIC-002

Staff must build quizzes with typed questions, correct answers, and rules.

**Acceptance Criteria:**
1. Given the quiz builder, when a question is added, then a question type (multiple choice, true/false, multiple answer, short answer) and its correct answer(s) are captured; for choice types the correct option is explicitly marked.
2. Given quiz settings are configured, then pass mark, attempts allowed, feedback mode (show correct answers / score only / after all attempts), shuffle, "required to complete module", and the recorded-score rule are persisted; the recorded score is the youth's best passing attempt within the configured attempt limit (align with L2-LEARN-004).
3. Given questions, when reordered, then the order persists (subject to shuffle at delivery).
4. Given a saved quiz, when a youth takes it, then scoring uses exactly the configured correct answers and pass mark (see L2-LEARN-004).

## L2-CURRIC-004: Assignment authoring
**Traces to:** L1-CURRIC-003

Staff must define assignments with submission types, a rubric, and due rules.

**Acceptance Criteria:**
1. Given the assignment builder, when saved, then title and task description are required and at least one submission type (text/photo/link/file) must be selected.
2. Given the rubric, when defined, then each criterion has a point value and the total possible points is computed and stored.
3. Given due rules, when set, then due date, grace period, allow-late (flagged for mentor), and "require mentor approval before complete" are persisted.
4. Given an assignment, when published to cohorts, then it is assigned to youth in the module's cohorts.

---

## L2-CURRIC-005: Badge authoring and awarding rules
**Traces to:** L1-CURRIC-004

Staff must define badges with auto or manual award rules and optional competency mapping.

**Acceptance Criteria:**
1. Given the badge builder, when saved, then name, icon, description, and criteria kind (auto rule vs. manual) are persisted; auto badges specify the triggering rule and may map to a competency.
2. Given an auto-award rule (module completed, lesson completed, quiz passed, attendance streak, assignment approved), when a youth meets it, then the badge is awarded automatically exactly once and a notification/real-time event fires (see L2-NFR-005).
3. Given a manual badge, when a mentor or Program Administrator awards it to a youth, then the badge is awarded to the youth with the awarder identity and timestamp captured and audit-logged (see L2-CONSENT-003).
4. Given a badge is deleted, when confirmed, then youth who already earned it keep it, but no new youth can earn it.

## L2-CURRIC-006: Progression framework authoring
**Traces to:** L1-CURRIC-005

Staff must define ordered stages and their competencies.

**Acceptance Criteria:**
1. Given the progression editor, when a stage is added, then its name, description, and order are persisted.
2. Given a stage, when a competency is added, then it is associated with that stage; competencies can be removed and stages reordered.
3. Given the framework, when saved, then it is used to compute each youth's current stage and to populate competency assessment (see L2-MENTOR-005) and reports.
