# L2 — Reporting & Data (REPORT)

Each L2 traces to an L1 in `reporting-and-data/L1.md`.

## L2-REPORT-001: Standard reports
**Traces to:** L1-REPORT-001

Staff must access org, youth, cohort, attendance, and staff reports with filters.

**Acceptance Criteria:**
1. Given the reports hub, when filters (date range, cohort, track, mentor) are applied, then KPIs and charts recompute for that scope and an updated-timestamp/record-count is shown.
2. Given the individual-youth report, when generated, then it shows progress rings, module completion, quiz scores, attendance breakdown, mentor-assessed competencies, mentor-notes summary, and badges for the selected youth.
3. Given the cohort report, when generated, then it shows enrolment, average completion, attendance, retention, module completion, and a youth summary with status counts, and supports comparison to program average/another cohort/previous term.
4. Given the staff-activity report, when generated, then it shows per-mentor caseload, check-ins, reviews, and load balance with overload warnings.
5. Given no data for the filters, when queried, then an empty state is shown; on load failure, an error state with retry.
6. Given report data, when served, then it is scoped to the requester's authorization (a mentor's reports cover only their youth — see L2-AUTH-010).

## L2-REPORT-003: Data export
**Traces to:** L1-REPORT-003

The system must export data in CSV and PDF, respecting filters and authorization.

**Acceptance Criteria:**
1. Given an exportable view (progress board, reports, attendance), when export is requested, then the output includes exactly the data within the current filters; export of the audit log is available only to Program Administrator (and director-level) roles, and is denied to all other roles.
2. Given a selected format, when exported, then CSV produces raw rows and PDF a formatted summary.
3. Given an export, when produced, then it contains only data the requester is authorized to see (see L2-AUTH-010), and the export action is audit-logged (see L2-CONSENT-003).

## L2-REPORT-004: Data import / roster migration
**Traces to:** L1-REPORT-004

Admins must import roster CSVs with column mapping, per-row validation, and import of valid rows only.

**Acceptance Criteria:**
1. Given a CSV upload, when parsed, then row/column counts are shown and the file type is validated (.csv only, within size limits — see L2-NFR-001).
2. Given the mapping step, when columns are mapped to system fields (Name/Email/Cohort/Mentor/Track/Status/Skip), then unmapped columns are skipped.
3. Given the preview step, when shown, then each row is validated with a status (Ready / Missing consent / Duplicate), and a summary of ready/needs-consent/duplicate counts is displayed.
4. Given "import", when confirmed, then only Ready rows are imported (duplicates skipped, missing-consent flagged for follow-up), the count imported is reported, and results are audit-logged (see L2-CONSENT-003).
5. Given import creates/updates people, when performed, then it is idempotent on re-run (matching by email) and never creates duplicate accounts.
