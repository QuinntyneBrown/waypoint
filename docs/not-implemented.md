# Required implementation gaps

Snapshot: **2026-07-18**

This document lists user-facing pages and supporting functionality that are still required by the in-scope requirements under `docs/specs/` but are not fully implemented in the production Angular applications and backend.

## How this inventory was produced

- The 88 in-scope L2 requirements are the scope authority. `docs/specs/out-of-scope.md` is excluded.
- Angular routes and components under `frontend/projects/portal` and `frontend/projects/public-site` are the authority for implemented pages.
- Controllers and application handlers under `backend/src` are the authority for implemented server behavior.
- Static HTML under `docs/mocks/` is a design reference, not an implementation.
- A controller, test, mock, or trace comment alone does not prove an end-to-end requirement complete. For example, the strict traceability check currently finds test references for 86 of 88 L2 IDs, but many of those tests cover only a server slice while the required page or another acceptance criterion remains absent.

Status terms used below:

- **Missing** — there is no production page or no meaningful implementation of the required outcome.
- **Partial** — a route, page, or server slice exists, but at least one required behavior is absent, placeholder-only, or not wired end to end.
- **API available/partial** — describes server support for a missing page; it does not make the page implemented.

## Current implemented boundary

The public application currently routes to landing, programs, apply, get involved, donate, contact, privacy, and not-found pages. The authenticated portal currently routes to sign-in/password recovery, onboarding, three youth pages (home, announcements, notifications), profile/notification/display settings, support, and shared state pages.

There are no production feature routes for Program Administrator, Mentor, Guardian, or Volunteer users. `roleHome()` can return `/admin/dashboard`, `/mentor/dashboard`, `/guardian/home`, and `/volunteer/home`, but those routes fall through to the portal's 404 page.

The backend is substantially broader than the UI. It contains APIs for most domains, but several APIs expose only the first slice of the associated requirement. The gap lists below distinguish missing UI from missing server behavior.

## Requirement conflicts to resolve

These are not optional features. The in-scope requirements currently disagree, so one side must be corrected before the implementation can be declared complete.

| Conflict                           | Current implementation                                                                                                                                                                                                                       | Requirements                              |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| Volunteer roster safeguarding data | Authentication visibility says a volunteer roster includes name plus an at-risk flag, while the Volunteer requirement explicitly permits names only and prohibits the at-risk flag. The API currently returns names only.                    | `L2-AUTH-010` AC3; `L2-VOLUNTEER-001` AC2 |
| Curriculum-editing role            | Curriculum authoring says Program Administrators and Mentors are authorized “per matrix,” while the actual permission matrix grants Edit curriculum only to Program Administrators. The API currently follows the matrix and denies Mentors. | `L2-CURRIC-001` AC5; `L2-AUTH-009` AC5    |

## Explicitly excluded

The following prototype screens/features are intentionally **not** implementation gaps because their requirements were retired or narrowed in `docs/specs/out-of-scope.md`:

- PIN sign-in and remembered-account/switch-user picker
- offline learning beyond attendance
- broad real-time domain-event fan-out beyond notifications/messages
- localization/language selection
- coding cohort gallery
- Google Workspace/Drive and live Google Sheets integration
- custom report builder/saved presets
- global search
- web push/quiet hours
- RSVP waitlisting/capacity
- automatic volunteer-hours totals
- federated sign-in and a light/dark theme toggle

The static mocks for those features may remain in `docs/mocks/`, but they must not be treated as v1 work unless the PRD and in-scope requirements are changed first.
