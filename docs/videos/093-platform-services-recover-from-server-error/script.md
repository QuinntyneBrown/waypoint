# 093 · When something goes wrong on our side

## Welcome

Sometimes the problem is not the person at the keyboard. The server hits an unexpected error. This video shows what Waypoint shows in that moment, and how it protects what the person was typing.

[pause 2s]

## A message that does not send

David Osei is on the contact support page. He has chosen what his question is about, and he has typed a message. It says that the lesson page will not open for him, and that he tried twice this morning. He presses send message.

This time the server fails to handle the request. David did nothing wrong. Waypoint keeps what he typed, and it does not pretend the message was sent.

[pause 2s]

## Something went wrong

Waypoint opens a page headed, something went wrong. A small label above it says, error five hundred. The text is calm and honest. We hit a snag on our end. Nothing you did caused it. Please try again in a moment.

There is no stack trace, no file name, and no technical jargon on the screen. Those details stay on the server side, where the error is recorded for the team.

There are two buttons. Try again, and back to home.

[pause 2s]

## Nothing is lost

David presses try again. Waypoint takes him back to the support page, and the message he typed is there, word for word. His reply email is there too. He does not have to write it all again.

If he would rather leave, back to home takes him to the home made for his role.

[pause 2s]

## Things to remember

When the server fails, the person sees a friendly page that says it was not their fault. Technical details are never shown on screen. Try again returns to the page and puts back what the person was typing, so a failure does not cost them their work.
