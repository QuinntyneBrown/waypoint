# 079 · Recording audit events

## Welcome

Waypoint writes an audit entry whenever someone does something that matters for security or safeguarding. Nobody has to remember to do it. This video explains what is recorded, what each entry holds, and how the record is protected.

[pause 2s]

## What gets recorded

Grace Adeyemi is a mentor. She signs in to Waypoint, and then she logs a private check-in with Amara Bell. Neither step involves any extra work for Grace. Behind the scenes, each one writes an entry to the audit trail.

The program records every change that matters. Approving an application. Changing a role. Editing a lesson. Taking attendance. Logging a check-in. Awarding a badge. Signing in. Deactivating an account.

[pause 2s]

## What an entry holds

Pat Morgan, a program administrator, opens the audit log and filters it to Grace. Each entry answers the same questions. Who did it. What the action was. What it was done to. When it happened. And the source, which is the device and the place it came from, where Waypoint could capture it. Where it could not, the page says, not captured.

For the check-in, the entry says it was private, and the note itself is redacted. Waypoint proves that the check-in happened, without copying what was said into the log.

[pause 2s]

## Protected from change

The audit trail is append only. Entries are added, but no screen lets anyone edit or delete one, not even a program administrator. The entries are also chained together, so that tampering can be detected. If the check fails, the audit log page shows a red warning.

Only program administrators can read the log. Everyone else sees nothing of it.

[pause 2s]

## Things to remember

Important actions write an audit entry automatically. Each entry records who, what, to what, when, and from where. Private note content is redacted. The trail cannot be edited or deleted through the application, and only program administrators can read it.
