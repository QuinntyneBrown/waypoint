Data tables and lists

Density, sorting, filtering, selection and mobile strategy.

Overview

Admins live in tables; youth and guardians see lists and cards.

When to use

  • Table: compare records across fields.
  • List: scan a single field (people, notifications).
  • Cards: browse visual items (tracks, badges).

States

  • Loading: skeleton rows. Empty: empty state in the body. Error: alert above the table with retry.
  • Selection shows a bulk bar.

Responsive

  • Cards under 768px via .ph-table--cards.
  • Filters collapse into a Filter button + drawer on phones.

Accessibility

  • Caption, scope, aria-sort; per-row labelled actions.

Content

  • Headers short nouns; empty cells say "Not provided".
