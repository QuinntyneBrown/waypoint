Overview

Match the feedback to the scope of the change.

When to use

SituationUse
Action done, nothing to doToast
Problem in one fieldInline message
Problem with a sectionAlert
App-wide conditionBanner
Decision neededDialog
Page content loadingSkeleton
Button action runningBusy button
Known-length taskProgress bar

Structure

Lesson saved
Busy button, skeleton, toast.
HTML
<div class="w-stack w-stack--sm" style="width:100%"><button class="w-btn w-btn--primary" type="button" aria-busy="true">Save</button><div class="w-card" aria-busy="true"><div class="w-card__body"><span class="w-skeleton w-skeleton--title" aria-hidden="true"></span><span class="w-skeleton w-skeleton--text" aria-hidden="true"></span></div></div><div class="w-toast" role="status"><div class="w-toast__body">Lesson saved</div><button class="w-toast__action" type="button">Undo</button></div></div>

States

  • Optimistic updates for low-risk actions (mark as read), with undo.
  • Pessimistic (wait) for consent, payments, removals.

Responsive

  • Toasts sit above the bottom nav on phones.

Accessibility

  • One polite live region for status; role="alert" only for errors.
  • Loading regions set aria-busy.

Content

  • Past tense confirmations: "Saved", "Invite sent".
