Form layout

How fields, fieldsets, the error summary and the actions bar compose into a form.

WCAG 2.2 AALight + dark

Overview

One column by default; two columns only for short related pairs (first/last name) at 768px and up. Actions sit at the end, primary last.

Anatomy

  1. Error summaryDanger alert listing each error as a link to its field; receives focus on submit.
  2. FieldsOne column, 20px apart.
  3. Actions barBack left, primary right.

Variants

Two-column pair.
HTML
<div class="w-grid w-grid--2"><div class="w-field"><label class="w-label" for="fn">First name</label><input class="w-input" id="fn" autocomplete="given-name"></div><div class="w-field"><label class="w-label" for="ln">Last name</label><input class="w-input" id="ln" autocomplete="family-name"></div></div>

Sizes

Forms are constrained by --layout-container-narrow (760px).

States

Pointer and focus states are forced with data-state so they can be reviewed statically; real pages get them from :hover, :focus-visible, :active and ARIA attributes.

VariantDefaultSubmitting
Submit

Both themes

On submit the primary button goes busy; other fields stay editable but submit is ignored until the request finishes.

Responsive behaviour

  • Two-column pairs collapse to one below 640px.
  • Actions stack, primary first, full width on phones.

Theming

Uses component tokens of its parts only.

Dark theme applies with [data-theme="dark"] or the OS preference; the component itself has no theme-specific CSS.

Accessibility

Role and pattern

<form novalidate> with custom messages; error summary role="alert", focus moved to it on failed submit.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the control in DOM order.
EnterSubmits from a single-line input.

Focus

Moves to the error summary on failed submit, then to the field when a link is followed.
