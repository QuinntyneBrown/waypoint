Icon button

A round, borderless button holding a single icon: the top-bar actions, row menus and dialog close buttons.

WCAG 2.2 AALight + dark

Overview

Use an icon button when space is tight and the icon is universally understood (close, menu, notifications, more). If the meaning needs a word, use a button with an icon and a label instead.

Anatomy

  1. Icon20px stroke icon, aria-hidden.
  2. Indicator dot (optional)8px tomato dot for unread state; the count is also in the accessible name.
  3. Hit area44px circle; hover fills with --color-bg-subtle-hover.

Plain, with an unread dot, and small for table rows.

States

Pointer and focus states are forced with data-state so they can be reviewed statically; real pages get them from :hover, :focus-visible, :active and ARIA attributes.

Responsive behaviour

  • Top-bar icon buttons stay visible at every width; the menu (burger) button only appears below 960px.
  • Never shrink below 32px; on phones prefer the 44px size.

Theming

Transparent at rest, --color-bg-subtle-hover on hover, icon in --color-fg-default. The unread dot is --color-danger-icon with a ring in --color-bg-surface so it reads on any surface.

Dark theme applies with [data-theme="dark"] or the OS preference; the component itself has no theme-specific CSS.

Accessibility

Role and pattern

Native <button> with aria-label. When it opens something, add aria-haspopup and aria-expanded.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the control in DOM order.
Enter, SpaceActivates the control.

Focus

Shared focus ring around the circle.

Labelling

Always aria-label with verb and object; include unread counts in the name ("Notifications, 2 unread"). Pair with a tooltip.

Touch

44px by default. The 32px size needs 8px spacing to neighbours.

Content

  • The label is the verb: "Close", "Open menu", "More actions for Maya Ortiz".
  • Do not use an icon button for an action people cannot guess from the icon.
