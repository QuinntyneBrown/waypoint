Form field

The wrapper every input uses: label, control, help, error and counter, in a fixed order and spacing.

Overview

Wrap every control in .ph-field. It owns the vertical rhythm (8px label gap, 4px to help, 20px between fields) and error presentation.

Anatomy

  1. Label + required markerAsterisk is decorative; required carries meaning.
  2. ControlAny input.
  3. HelpPersistent hint.
  4. ErrorShown when invalid; icon plus text.

Variants

Optional field marker.
HTML
<div class="ph-field"><label class="ph-label" for="fo">Church <span class="ph-label__opt">(optional)</span></label><input class="ph-input" id="fo" type="text"></div>

Sizes

Spacing is fixed; the control decides its size.

States

Pointer and focus states are forced with data-state so they can be reviewed statically; real pages get them from :hover, :focus-visible, :active and ARIA attributes.

Responsive behaviour

  • Labels stay above controls at all widths (never left-aligned) so long translations wrap.

Theming

Sets --field-border for its control; the error state swaps it for --color-danger-solid.

Component tokens (declared in components.css, override per variant or theme): --field-border.

Dark theme applies with [data-theme="dark"] or the OS preference; the component itself has no theme-specific CSS.

Accessibility

Role and pattern

<label for>; help and error ids listed in aria-describedby; aria-invalid on the control.
