Button

Buttons start an action: save, send, invite, delete. One lime primary button per view tells people what matters most.

Overview

Use a button when activating it changes something: it submits, creates, deletes, opens a dialog or starts a process. Use a link when it only goes somewhere, and a menu when one trigger offers several actions.

  • Primary (lime) is the one action the view exists for. Never two per view.
  • Secondary (ink) is a strong action that is not the main one, such as "Message mentor" next to "Start lesson".
  • Ghost (outlined) is the everyday button: Cancel, Export, Edit in a card header.
  • Subtle (greige) sits on dense surfaces: filters, row tools.
  • Danger appears only inside a confirmation dialog.
  • Link looks like a link but behaves like a button; use it for low-emphasis actions inside text.

Anatomy

  1. Leading icon (optional)18px, inherits the label colour, aria-hidden.
  2. LabelSpace Grotesk 500, a verb phrase in sentence case; the accessible name.
  3. ContainerPill (--radius-full), height from --control-height-*, 1.5px border slot.

Sizes

Medium is the default. Small lives in tables, card headers and toolbars; large is for auth screens and public heroes.

Both themes

  • Loading keeps the width, hides the label behind a spinner, sets aria-busy="true" and ignores clicks.
  • Disabled is 50% opaque and not focusable. Prefer an enabled button that explains the problem on press.
  • Pressed (toggle) uses aria-pressed="true" and turns ink; see button group.

Responsive behaviour

  • Below 640px the primary action in a page header or form becomes full width (.w-btn--block); secondary actions stack beneath it.
  • Dialog footers stack on phones with the primary on top (column-reverse) and every button full width.
  • Medium (44px) and large (52px) meet the comfortable touch target; small (32px) only appears in rows where neighbours are 8px apart.
  • Labels never truncate. A label that wraps at 360px is too long; shorten it.

Theming

The button reads four component tokens: --btn-bg, --btn-fg, --btn-border, --btn-bg-hover. Each variant points them at semantic tokens. In dark, primary stays lime with ink text; secondary reads the inverse tokens, so it becomes a light greige pill with ink text and stays distinct from the lime primary.

Component tokens (declared in components.css, override per variant or theme): --btn-bg, --btn-fg, --btn-border, --btn-bg-hover, --btn-height, --btn-pad.

Dark theme applies with [data-theme="dark"] or the OS preference; the component itself has no theme-specific CSS.

Accessibility

Role and pattern

Native <button type="button"> (or type="submit" in a form). A link styled as a button is still an <a href>. Toggle buttons add aria-pressed.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the control in DOM order.
Enter, SpaceActivates the button. Space fires on key up, so moving away cancels a mis-press.

Focus

The shared 2px ring in --color-focus-ring (ink in light, lime in dark) with a 3px offset, on :focus-visible only.

Labelling

The visible label is the accessible name. Icon-only buttons need aria-label naming the verb and object ("Edit lesson") and a tooltip. Loading buttons keep their name and add aria-busy; announce progress through a live region.

Motion

Colours ease over --duration-fast; active nudges 1px down. Reduced motion zeroes the durations in the tokens. The loading spinner keeps turning because it is status, not decoration.

Touch

Medium and large exceed 44px. Keep 8px (--space-2) between adjacent buttons.

Content

  • Labels are verb phrases in sentence case: "Invite youth", "Submit work", "Approve application". Never "OK", "Submit", "Click here".
  • Name the object when context does not: "Remove mentor" in a dialog, "Remove" in a row.
  • Destructive labels name the loss: "Delete 3 lessons", not "Confirm".
  • Keep to three words where possible.
