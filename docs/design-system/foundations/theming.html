Theming

Light and dark from one token file; brand themes by overriding semantic tokens only.

WCAG 2.2 AALight + dark
  • Overview
  • Token tiers
  • Adding a theme
  • tokens.json
  • User preferences

Overview

Light is :root. Dark applies with [data-theme="dark"] on any element, or automatically when the OS prefers dark and the page has not forced data-theme="light". Each theme sets color-scheme so native controls follow.

The mocks are light-only; the dark theme is built from roles: warm ink surfaces that lighten as they rise, lime as the accent, deep status tints with light text.

Token tiers

  • Primitives (--palette-*, --font-*): raw values.
  • Semantic (--color-*, --space-* …): what components read; themes override only these.
  • Component (--btn-*, --field-border, --badge-*, --alert-*): scoped aliases in components.css.

Adding a theme

[data-theme="partner"] {
  --color-brand: var(--palette-teal-300);
  --color-fg-on-brand: var(--palette-ink-900);
}
  • Override semantic tokens only.
  • Add the theme to contrast-pairs.json and run check_contrast.py.
  • Never fork components.css for a theme.

tokens.json

tokens/tokens.json is the DTCG export ($type, $value, aliases as {group.token}, dark values under $extensions). Regenerate it with tokens_to_json.py after editing tokens.css; generate platform constants from it.

User preferences

  • prefers-contrast: more raises borders and muted text to stronger tokens.
  • forced-colors: active hands focus ring and borders to system colours.
  • prefers-reduced-motion zeroes durations.
